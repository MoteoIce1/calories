# План миграции в мобильное приложение (App Store + Google Play)

Документ для переписывания текущего PWA (React + Vite + Firebase) в нативное приложение
и публикации в сторах. Бэкенд переиспользуется как есть.

## 1. Текущее состояние

- **Фронт:** React + Vite, один большой `src/App.jsx` (~3300 строк), PWA.
- **Бэкенд (переиспользуется без переписывания):**
  - Firebase Auth (email/пароль), Firestore, Hosting.
  - Cloud Functions (`functions/index.js`): `calcRecipe`, `parseIngredients` (ИИ-разбор
    рецептов через Anthropic), `deleteAccount` (удаление аккаунта). Дневной лимит ИИ,
    дедуп-кеш, App Check.
  - Секрет `ANTHROPIC_API_KEY` в Secret Manager.
- **Данные (Firestore):**
  - `users/{uid}` — профиль, цели; подколлекции `days/{date}` (дневник, шаги, вода, метрики)
    и `body/{id}` (замеры тела + фото base64). **Доступ только владельцу** (правила).
  - `shared/foods` — общая база продуктов (пишет владелец, читают все).
  - `publicProfiles/{uid}` — только имя + код друга (поиск, подписи). Без показателей здоровья.
  - `connections/{id}` — связи (друзья), `challenges/{id}` — споры (живые данные метрики
    спора лежат внутри документа, читают только участники).
  - `aiUsage/{uid}` — счётчик ИИ/день. `aiCache/{hash}` — кеш ИИ-ответов.

## 2. Выбор стека: Capacitor vs React Native

| Критерий | Capacitor (обёртка) | React Native (Expo) |
|---|---|---|
| Переиспользование кода | ~100% текущего React | только бэкенд + чистая логика |
| Срок до сторов | дни–недели | месяцы |
| Нативный UX/перформанс | средний | высокий |
| Риск отклонения Apple (4.2) | есть для «тонких» обёрток | нет |

**Рекомендация:** начать с **Capacitor** (быстро в сторы, весь код остаётся), перейти на
полный RN только при упоре в UX/перформанс. Бэкенд (Firebase) одинаков для обоих путей.

## 3. Подготовка кода (до миграции)

1. **Вынести бизнес-логику из `App.jsx` в `src/core/`** — чистые модули без UI:
   - расчёт КБЖУ (`computeKbju`), дефицит/норма с учётом шагов, серия;
   - логика споров (стендинг, цели, дельты), КБЖУ-математика;
   - обёртки ИИ-вызовов (`calcRecipe`, `parseIngredients`).
   Уже вынесено: `utils/food.js` (поиск с морфологией), `utils/date.js`, `utils/math.js`,
   `utils/stats.js`. Цель — чтобы переписывался только UI, а логика переезжала как есть.
2. **Firebase в мобиле:** Capacitor — текущий JS SDK работает; RN — `@react-native-firebase/*`
   (нативный, лучше для пушей/Firestore) или JS SDK в Expo.
3. **Графики:** сейчас самописные SVG (`Charts.jsx`) — в RN заменить на `react-native-svg`
   (почти 1:1), в Capacitor работают как есть.

## 4. Требования сторов (часть — блокеры)

- [ ] Apple Developer ($99/год), Google Play Developer ($25 разово).
- [x] **Удаление аккаунта в приложении** — сделано (Cloud Function `deleteAccount` + кнопка).
- [ ] **Политика конфиденциальности (URL)** — см. `PRIVACY.md`, нужно опубликовать
      (можно на Firebase Hosting: `/privacy`).
- [ ] **Apple Privacy Nutrition Labels** + **Google Data Safety** — задекларировать сбор:
      e-mail, данные о здоровье (вес, замеры), фото тела. Данные о здоровье — чувствительная
      категория.
- [x] **Дисклеймер «не медицинский совет»** — добавлен (вход, профиль, онбординг).
- [ ] **Подписка только через IAP** (Apple StoreKit / Google Play Billing). «Поднять лимит
      ИИ за деньги» — через **RevenueCat** (обе платформы). Не Stripe для цифровых товаров.
- [ ] **App Check на мобиле** → Play Integrity (Android) + App Attest/DeviceCheck (iOS)
      вместо веб-reCAPTCHA.
- [ ] **Разрешения iOS:** `NSCameraUsageDescription`, `NSPhotoLibraryUsageDescription`
      (фото тела).
- [ ] Иконки, сплэши, скриншоты под размеры; возрастной рейтинг; описание/ключевые слова.
- Sign in with Apple — **не требуется** (только email/пароль, без соц-логинов).

## 5. Экраны приложения (для переписывания)

1. Вход / регистрация / сброс пароля + **онбординг** (пол, возраст, рост, вес, активность,
   дефицит, минимум шагов → норма КБЖУ).
2. Дневник: добавление приёма пищи (поиск/база), «Рецепт ИИ», вода, шаги, метрики дня.
3. База продуктов: список, добавление вручную, «КБЖУ из рецепта».
4. Прогресс: графики веса/жира/метрик, замеры тела + фото, сравнение.
5. Профиль/настройки: цели, тема, шрифт, блоки, выход, **удаление аккаунта**.
6. Друзья и споры: код друга, заявки, споры (вес/жир/талия/шаги/дефицит/серия) + тренды.

## 6. Порядок работ

1. ✅ Удаление аккаунта, сброс пароля, онбординг, дисклеймер, напоминание о замерах.
2. Вынести логику в `src/core/`.
3. Опубликовать `PRIVACY.md`, завести Apple/Google аккаунты.
4. Выбрать Capacitor/Expo, собрать первый билд, добавить нативные плагины (камера, пуши, IAP).
5. App Check на нативной аттестации, IAP-подписка через RevenueCat.
6. Скриншоты/иконки, заполнить Data Safety / Nutrition Labels, отправить на ревью.
